# SleepControl

简体中文 · [English](README.md)

一款免费、开源的 macOS 菜单栏工具，用来管理合盖、接电源以及本机 AI 任务运行期间的休眠设置。

界面、帮助和诊断信息支持简体中文、繁体中文、英语、德语、法语、西班牙语、日语、韩语、葡萄牙语（巴西）和意大利语，按 macOS 的首选语言自动选择，没有匹配语言时显示英文。繁简中文会按文字及地区匹配，例如台湾、香港、澳门中文使用繁体。修改系统或单个应用的语言设置后，重新打开应用即可。

## 功能

- 合盖后保持电脑运行。
- 接电源时防止电脑闲置休眠。
- Codex 或 Claude Code 的本机任务运行时暂不休眠，等待你输入或批准操作时不继续阻止休眠。
- 分别设置使用电池和接电源时的显示器关闭时间。
- 在菜单栏显示电量、充电状态和可选的电量百分比。
- 登录时自动启动。

## 系统要求

- macOS 13 Ventura 或更高版本。
- 下载与你的处理器匹配的安装包：`arm64` 适用于 Apple 芯片，`x86_64` 适用于 Intel。
- 从源码构建需要 Xcode 15 或更高版本，或带 Swift 5.9 及以上版本的 Command Line Tools。

AI 检测是可选功能。没有安装 Codex 或 Claude Code，也能使用其他休眠开关。

## 安装

1. 前往 [Releases](https://github.com/RayStudioLabs/SleepControl/releases)，下载适合你的 Mac 的 DMG（如有对应架构的安装包）。
2. 打开 DMG，把 **SleepControl** 拖到 **Applications（应用程序）**。
3. 推出磁盘镜像，再从“应用程序”打开已安装的 SleepControl。
4. 点击菜单栏中的电池图标打开设置面板，再次点击即可关闭。面板每次打开时自动读取最新设置，应用运行期间也会定时刷新。

安装盘中的应用文件名为 `SleepControl.app`。如果旧版文件名是 `SleepControl（Mac 休眠控制）.app`，请先退出旧版，再用新版替换它，保留一份安装即可。

当前构建使用本地 ad-hoc 签名，**尚未经过 Apple 公证**。首次运行可能被 macOS 阻止。确认下载来源后，如果系统提供该选项，可到“系统设置 → 隐私与安全性”中选择“仍要打开”。也可以自行从源码构建。

应用平时只在菜单栏运行，不出现在 Dock 和 Command-Tab 列表中。使用说明窗口被其他窗口挡住时，可以重新打开菜单栏面板，再点问号把它置前。

## 休眠开关如何工作

| 设置 | 实际作用 |
| --- | --- |
| 合盖后防止自动休眠 | 修改全局 `pmset disablesleep` 标志。**它会禁止所有系统休眠，不仅是合盖休眠。** |
| 接电源时防止自动休眠 | 把接电源时的闲置休眠时间设为“永不”；关闭后设为一分钟。 |
| AI任务执行时不休眠 | 检测到本机 AI 正在工作时，暂时阻止休眠；任务停下后恢复你设定的规则。 |
| 锁屏 | 分别设置电池和接电源时的显示器关闭时间，不是单独设置安全锁屏的时间。 |

前两个开关优先。如果它们的设置已经让电脑不休眠，AI 开关就不需要另外起作用。两个开关都打开时，AI 开关会隐藏，并保留之前的选择。

电脑原本应该休眠时，AI 开关会把休眠推迟到所有已检测任务都停下来。约两秒后，应用会重新检查电源、合盖情况和开关设置。开盖时恢复原来的设置，交给 macOS 决定何时闲置休眠；合盖且仍应休眠时，主动请求休眠。

**合盖后电脑仍可能运行并发热。请保持通风，不要在禁止休眠时把电脑装进包里。** `disablesleep` 不是 Apple 公开文档中的接口，硬件或系统更新可能影响其行为。

## 管理员权限

第一次修改电源设置时，应用可能要求输入管理员密码。授权后，会创建 `/etc/sudoers.d/lidcontrol`，允许当前 macOS 用户通过 `sudo` 免密执行 `/usr/bin/pmset`。

这项权限不仅供 SleepControl 使用，也适用于当前用户的其他 `pmset` 调用。它会在重启后继续保留，删除应用也不会自动移除。已有权限时不会重复申请。移除方法见下方“卸载”。

## 可选的 AI 任务检测

1. 打开 **AI任务执行时不休眠**。应用会安装本机助手，并添加自己的钩子，保留其他配置。
2. **Codex 命令行版**：输入 `/hooks`，进入各个事件的命令详情，检查并信任含有 `SleepControlHelper` 和 `# sleepcontrol-ai-observer` 的钩子。需要检查所有 SleepControl 条目，不能只设 `SessionStart`。
3. **Claude Code**：用 `/hooks` 确认有同样的助手和标识，不需要像 Codex 那样逐项设置信任。确认钩子没有被禁用。
4. 运行一个本机任务，观察说明窗口底部的 **AI休眠保护状态**，确认开始执行、结束和等待你操作时，状态能相应变化。

如果找不到新钩子，彻底退出相应客户端后再打开检查。输入 `/clear` 不代表配置已重新加载。详细步骤在应用的使用说明中，也可查看 [AI 接入说明](docs/AI-INTEGRATION.md)。

### 哪些任务会保持不休眠

正在思考、生成回答、等待服务器返回、执行工具，以及尚未结束的子任务和后台命令，都算正在工作。等待你输入、做选择或批准操作时不算；如果还有其他任务在运行，仍会继续保护。

目前支持**本机 Codex 和 Claude Code 会话**。桌面版 Code 任务需要使用同一个本机引擎和配置，并能正确传回状态。普通 Claude 聊天、Cowork、云端任务，以及通过 SSH 在远程电脑运行的任务，不能保证识别。

客户端的状态接口可能随版本变化。检测失联或状态未知时，应用不会直接认定任务已经完成，会保留已有保护，直到检测恢复或你关闭 AI 开关。用于无人值守任务前，请先用自己的客户端版本实际验证。

## 隐私和本地文件

应用只在本机保留会话标识、任务生命周期状态和进程标识，不保存提示词、回答或工具参数。SleepControl 没有统计分析服务或远程服务器；AI 客户端自己的网络请求与本应用无关。

项目原名为 **LidControl**。为兼容已有安装，保留以下标识和路径：

- 应用标识：`com.daichenyu.lidcontrol`。
- 助手、状态和配置备份：`~/Library/Application Support/LidControl/AI/`。
- 免密电源设置规则：`/etc/sudoers.d/lidcontrol`。

助手名为 `SleepControlHelper`，钩子标识为 `sleepcontrol-ai-observer`。

## 从源码构建

```bash
git clone https://github.com/RayStudioLabs/SleepControl.git
cd SleepControl
swift test
./scripts/build-app.sh
```

应用生成在 `build/SleepControl.app`。请把完整的 `.app` 复制到“应用程序”，不要只复制可执行文件：应用和独立 AI 助手都需要语言资源。

生成适合当前处理器架构的拖放安装包：

```bash
./scripts/build-dmg.sh
```

打包 DMG 还需要 Python 3.10 或更高版本。首次运行时，脚本会将固定版本的打包工具下载到 `.build/dmg-tools/`，这些工具不会装进应用。可通过 `DMG_PYTHON` 指定 Python 路径。安装盘打开后会显示适配 Retina 的背景、固定位置的应用图标和 Applications 快捷方式，协议与安装说明放在隐藏的 `.documentation` 文件夹中。

输出为 `build/SleepControl-<版本>-<架构>.dmg` 及 `.sha256` 校验文件。脚本不会自动生成通用二进制。最低部署目标为 macOS 13；Intel 版本需要另外构建和验证。

测试使用临时配置和模拟电源驱动，不会修改真实电源设置或让电脑进入休眠。

## 卸载

1. 关闭 AI 保护和“登录时自动启动”，然后在面板中选择 **退出**。正常退出会恢复 AI 保护期间临时修改的休眠设置。
2. 在 Codex 和 Claude Code 的配置中，只移除带 `sleepcontrol-ai-observer` 标识的 SleepControl 钩子，保留其他钩子和设置。重新打开客户端，避免继续调用旧助手。
3. 把“应用程序”中的 SleepControl 移到废纸篓。确认没有客户端继续使用助手后，可以移除 `~/Library/Application Support/LidControl/AI/`，其中包括本地状态和备份。
4. 如需撤销免密执行 `pmset` 的权限，删除本应用创建的规则：

   ```bash
   sudo rm /etc/sudoers.d/lidcontrol
   ```

两个手动开关直接修改系统电源设置，会独立于应用保留。卸载前请先调整成你需要的状态；删除应用不会把所有电源选项重置为出厂值。
